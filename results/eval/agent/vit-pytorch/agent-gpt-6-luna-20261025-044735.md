# AgenticTorch report: vit-pytorch

**Result: 1.37x faster, loss within noise** on an NVIDIA L4.

- Command: `python train_vit_decorr.py`
- Baseline: 26.8 ms/step over 2 runs
- Model: gpt-6-luna, 17 turns, 96707 input and 747 output tokens

Set the DataLoader to use four persistent workers and pinned memory, reducing measured step time from 26.8 to 21.8 ms. Enabled fused Adam, which benchmarked faster again; best measured step time is 17.8 ms. Removing .item() from printing and torch.compile did not beat the best version and were reverted.

## Changes

| # | Change | Before | After | Outcome |
|---|---|---|---|---|
| 1 | Use four persistent DataLoader workers and pinned host memory to overlap CIFAR loading and enable faster host-to-GPU transfers. | 27.7 ms/step | 21.8 ms/step | kept: 1.27x faster, loss within noise |
| 2 | Remove explicit .item() calls from per-step loss printing to avoid forcing separate host-device synchronizations. | 22.0 ms/step | 21.8 ms/step | reverted: 1.01x is within noise |
| 3 | Enable Adam's fused CUDA implementation to reduce optimizer kernel launches while preserving the optimizer update. | 18.6 ms/step | 17.8 ms/step | kept: 1.04x faster, loss within noise |
| 4 | Compile the ViT module to reduce Python and kernel-launch overhead during repeated training steps. | 19.5 ms/step | 19.4 ms/step | reverted: 1.10x is within noise |
