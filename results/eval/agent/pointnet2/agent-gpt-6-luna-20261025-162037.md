# AgenticTorch report: pointnet2

**Result: 1.65x faster, loss within noise** on an NVIDIA L4.

- Command: `tar xf data/modelnet40_normal_resampled/subset.tar -C data/modelnet40_normal_resampled && python train_classification.py --model pointnet2_cls_ssg --log_dir agentictorch`
- Baseline: 280.4 ms/step over 2 runs
- Model: gpt-6-luna, 17 turns, 115254 input and 898 output tokens

The dominant bottleneck was boolean masked assignment in farthest-point sampling, which triggered nonzero operations and host-device synchronization on every sampling iteration. Replacing it with torch.minimum preserved the computation and was kept, improving measured step time from 280.4 ms to about 171 ms (1.67x). cuDNN autotuning, moving the accuracy reduction to GPU, and direct device allocation for batch indices did not beat the best version beyond benchmark noise and were reverted.

## Changes

| # | Change | Before | After | Outcome |
|---|---|---|---|---|
| 1 | Replace boolean masked distance update in farthest-point sampling with elementwise minimum, avoiding per-iteration nonzero and CPU synchronization. | 286.9 ms/step | 171.4 ms/step | kept: 1.67x faster, loss within noise |
| 2 | Enable cuDNN autotuning for the fixed-shape convolution workload to select faster convolution algorithms. | 174.1 ms/step | 171.6 ms/step | reverted: 1.01x is within noise |
| 3 | Keep the accuracy reduction on GPU instead of copying the prediction comparison tensor to CPU before summing. | 177.6 ms/step | 177.1 ms/step | reverted: 1.00x is within noise |
| 4 | Create farthest-point-sampling batch indices directly on the input device, avoiding a CPU allocation and transfer. | 169.7 ms/step | 170.8 ms/step | reverted: 0.99x is within noise |
