- Baseline: 182.1 ms/step over 2 runs
- Model: gpt-6-luna, 18 turns, 93982 input and 904 output tokens

Enabled CUDA TF32 matrix multiplication, which improved throughput by 1.13x (best measured 155.7 ms/step) with loss within noise. Fused Adam, DEBUG-check short-circuiting, and avoiding a CPU tensor allocation for the terminal distance were tested but did not beat the best version beyond noise and were reverted.

## Changes

| # | Change | Before | After | Outcome |
|---|---|---|---|---|
| 1 | Enable fused CUDA Adam to reduce optimizer kernel launches and overhead. | 178.7 ms/step | 179.2 ms/step | reverted: 1.00x is within noise |
| 2 | Short-circuit disabled DEBUG numerical checks before launching GPU reductions and synchronizations. | 176.4 ms/step | 176.0 ms/step | reverted: 1.00x is within noise |
| 3 | Create the terminal distance tensor directly on the existing tensor's device and dtype, avoiding CPU allocation and transfer. | 187.1 ms/step | 186.5 ms/step | reverted: 1.00x is within noise |
| 4 | Allow TF32 for CUDA matrix multiplications, accelerating the dominant linear-layer GEMMs on L4. | 176.5 ms/step | 155.7 ms/step | kept: 1.13x faster, loss within noise |
